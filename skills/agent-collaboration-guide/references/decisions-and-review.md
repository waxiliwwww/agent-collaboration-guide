# 决定、偏好与反馈闭环

用于跨轮决定、重复纠正、复盘和技能维护。普通小事直接沿当前对话完成；本篇不要求另建台账或每轮记录。

## 一份当前依据

先找当前任务或项目的需求、决定、Plan 与待办，保留目标、范围、约束、状态和下一步。明确反馈区分补充、替换与取消，更新同一依据；保留替换来由，不让旧记录阻止新要求。未决的重要取舍在对话中提出，不能只写进文件后继续。

已有决定且前提未变就沿用。改变主要结果、授权边界或代价才重新对齐；例行检查、可查事实和授权内可逆细节不转嫁用户。项目规则是默认方法与评判依据，可提出更好做法，须比较实际后果；偏离不绕过上级要求、用户决定或重要取舍确认。

## 反馈写到哪里

| 反馈的性质 | 保存位置与生效方式 |
| --- | --- |
| 本次目标、决定、待办或事实修正 | 当前任务／项目记录；保留本次范围 |
| 用户明确的长期选择或更正 | 私有 `local/preferences.md` 或其专题；及时写回，下一相关任务读取 |
| 根据行为提出的理解假设 | 私有观察，标为待验证，不改变稳定偏好或授权 |
| 可复用的通用方法候选 | 先脱敏并记录适用条件、证据、反例与代价，经维护审查再吸收 |

私有条目只需足以查到当前有效选择、适用范围、来源时间和替换状态。入口留短索引，项目或场景细节按需拆分；不复制整个聊天或公共方法。无信息就不猜，不因一个任务顺利或用户未回应就推断认可。

## 闭环如何运行

1. **触发。** 用户明确更正长期选择时立即处理；同类问题重复、阶段收口或要求沉淀时，归纳已经发生的摩擦，不重新访谈一遍。
2. **归因。** 检查规则是否缺失、入口是否能发现、是否未执行、检查是否只验了局部。先修当前成果与已有规则，不把个案措辞直接加进长清单。
3. **写回。** 按上表分流；同类合并，被替换内容移到历史。只读起草、发布和安装分别沿本轮授权，不把维护许可扩成任意外部动作。
4. **回用。** 下次相关任务开始时读有效项，落实成起草、执行或检查动作；纠正后检查整条关联逻辑，避免继续逐点补丁。
5. **检验与收敛。** 有适用任务时观察是否减少同类纠正和遗漏，同时看阅读、等待与维护成本；效果不明就保留未知，无效规则撤回或重写。不要以规则变多、记录已写或 AI 审阅通过宣布改进成功。

不建立默认定时复盘、每轮索评或无新信息的反馈仪式。只在缺少会影响后续的重要使用信息时集中提问。

## 什么能从偏好进入公共方法

候选应有超出某个用户／项目的明确机制、适用边界和合理代价，能解释旧规则哪里不够或为何没触发；去掉身份、路径、个人格式、固定数量与特有授权。已有通用条款可承接时直接合并，不增加同义条款。

明确的用户选择仍可立即在本机使用；公开吸收不等于普遍效果已验证。复杂修订用未参与起草者按原始请求审阅，必要时给未见过的代表任务进行前向演练，不喂预期答案或已知漏洞，再按实际结果修正。结构检查、行为样例、用户接受与持续收益分别说明。

公共条款已承接的方法从私有常驻偏好移除，私有层只保留用户具体选择和必要来源。历史另存可追溯，不默认加载。存放、更新保护与旧入口迁移见[本地配置](local-profile.md)。

## 独立复核怎样避免共同盲点

复核者先看原始任务、关键反馈、有效决定与实际成果，自行确定主要判断，再核查实现和差异；不只审作者摘要。看常见入口、生命周期、数据／执行交接、失败后果及保留成果，也检查多余确认、无用记录和转嫁工作。范围按风险裁剪，不要求多名 agent 各填同表。

发现问题指向具体依据和影响；修复后定向复核，保留首次问题与分歧，不能反复审到得到有利意见。没有所需独立意见或仍有实质分歧时说明，不自行视为通过。
