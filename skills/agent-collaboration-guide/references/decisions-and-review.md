# 决策与复核

用于需要跨轮沿用决定、维护项目约束、处理重要冲突或开展独立复核的工作。通用授权和推进方法沿[入口](../SKILL.md)；明确小修沿用已有请求即可，不要求逐项建档或审计。

## 先找到当前依据

开始、恢复、切换任务及相关修改前，从项目入口定位已有需求、设计、Plan 或决定记录，读关联的有效约束与未完成项。已有材料能承接就就地更新，不再建第二份规格或台账。缺少位置而任务确需持久接续时，沿项目文档约定维护一份记录并在已有入口说明位置；例如项目使用 `docs/decisions.md`，这是可选落位，不是所有项目的固定目录。

当前结论只维护一处，计划、任务和提交引用相关决定；大项目可沿已有功能或模块分节、编号和索引，不为每个微小判断单建文件。私有决定留在有权限的项目或用户记录中，不写入通用技能或公开材料。保存位置与实际访问条件应可定位；环境无法持久保存或另一会话无法读取时说明边界，不声称已有跨会话记忆保证。

## 哪些决定需要保留

用户明确敲定且影响后续工作的目标、约束、偏好和取舍应保存，不因 agent 将其评为低风险而忽略。agent 留存会影响使用行为、契约、架构、数据、明显成本或恢复方式的关键选择；常规实现细节无需逐条记。记录的是可复核的结论与简短依据，无需展开内部思考过程。

依实际内容区分本次选择、项目约束、长期偏好、事实及尚待检验的建议，说明来源和作用范围；不要求另填分类表。用户在一个任务中的选择不自动推广为长期偏好，推断出的偏好先标为推断。事实需要查证，“符合常识”应能落到具体使用情境和后果，不能代替证据或覆盖有效设计。

一段话或沿用现有格式，只需足以查到：决定了什么、谁在何种范围内决定、主要理由与必要替代、影响什么，以及当前状态与证据。重要取舍保留各主要选项的收益、代价及改选条件，不为凑选项发明弱方案。已建议、已决定、已实施和已验证分清，批准方案不等于已经完成或验收。

## 写回与冲突怎样闭环

明确反馈出现时及时更新同一依据；相关决策与修改前检索并核对。替换或取消时保留旧依据，注明新决定、生效范围与原因，避免把历史意见误当现行要求。用户已明确调整的直接写回并继续，不让保存旧决定阻止有效变更。

发现冲突先核对来源、范围、时效与已授权变更：实现偏离有效决定且可无损修复的自主修复；可查事实自行查证并说明；仅有 agent 的新推荐不能覆盖用户决定。需要改变目标、承诺或重要取舍而尚未授权时，暂停依赖部分，给出背景、可选做法、主要后果与推荐，主动请用户判断，其他已授权工作继续。一般偏好与具体决定不一致时结合适用范围处理，不能机械套用优先级掩盖真正矛盾。

已有授权内的高风险工作需要相应工程检查，不自动重新审批；低风险的新功能也可能改变范围。不能只按风险或模型自报置信度决定是否提问。需要用户判断的事项应在对话中提出，不能仅留在文件角落的“待定”项后报完成。

## 独立复核怎样发现遗漏

方案评估沿入口已有约定，关键成果交付复核按任务风险裁剪，复用适当的独立意见，不为每次编辑增加审查。让未参与该部分实施者接触原始请求与关键反馈、有效决定、实际成果或改动，以及已有证据和未测边界，自行形成验收问题；避免只沿作者整理的目录和清单查一次。

从用户实际使用及跨模块交接核对：常见入口与生命周期是否漏掉，设计或决定是否被静默改写，结果与失败是否能被接回，必要成本及副作用是否合理；也反向从实际差异寻找未登记的重要判断。并检查是否重复询问已有答案、要求用户补做可查事实、维护无用记录或依赖反复催促。维度按任务裁剪，不要求多名 agent 各填一份表。

发现应指到具体依据、影响及需要修复或决定的事项；修复后定向复核，不重复审到得到有利结论。保留首次问题与审阅分歧。独立 agent 意见、指定另一模型的评估、工程检查、真实使用和用户验收各说明实际取得了什么，不能相互替代。
