# 写作与机制解释

适用于文档、技术介绍、研究、方案和规格。需求、授权与通用接续沿总入口。本篇改变的是起草与审阅方法，不要求固定篇幅、图数或逐项填表。

## 起草前：先设计读者怎样建立理解

沿用读者目的、已有背景、原问题和认可主干。先形成标题应覆盖的对象关系、运行过程、关键规则与常见变化，再选择最简单的入口。正常路径是由点及面的起点，不能代替标题承诺的全貌；深浅按对理解与行为的影响安排，不让用户逐个补题。

读者已有具体问题时，先回答，再补解释答案所需的过程；一般机制介绍先建立整体关系。机制说明开头先交代当前处理方式、关键规则与后果及必要的扩展边界，后文围绕结论解释和取证，不让读者自行拼出核心逻辑。每次讲一层可以保持，但跨层依赖须在用到前简要介绍到足以理解，不能提前展开全部，也不能省略必要前提。

起草前选择关键关系的表达方式，与正文同时设计：

| 要看清的关系 | 适合的表达 |
| --- | --- |
| 组件、归属、接口与存储位置 | 架构／关系图 |
| 谁先处理、等待谁、何时保存或通知 | 时序图 |
| 判断依据及不同条件的结果 | 流程／状态图 |
| 多个对象同时推进或竞争资源 | 泳道／并发示意 |
| 条件、选项或证据的横向差异 | 表格 |

选择能实际减轻理解负担的图，不凑齐图种，也不把整段文字装进方框。图上标明实际传递物、接收者与必要判断，保持时序和数据依赖准确；逻辑归属、运行进程和代码目录分开。正文解释原因、条件和后果，避免将图和正文重复完整讲一遍。无需视觉表达的小事实直接说明。

## 正文：把因果与实现手段连起来

读者应能在同一主线上获得：为什么需要这项机制、什么触发它、谁拿到什么、依据什么判断、怎样处理、结果给谁，以及失败怎样接回。先补必要背景与术语；含糊的“恢复、匹配、保存、加载”要落实到对象、来源和处理过程，不能仅换成白话标签。

核心机制既不能止于用途，也不能变成代码清单。用一条有真实实现依据的过程支撑结论：数据怎样生成、保存何处、通过哪些关键标识关联、何时读取、缺失或不匹配怎样处理。决定理解的索引、关联键和失败去向默认可见；完整字段、函数链、源码与版本放补充层。折叠实现细账时，不连理解必需的手段一起隐藏。

先讲普通过程，再就近改变常见条件，说明原规则怎样导致不同行为。例子只证明其覆盖范围，不能把一个分支悄悄写成整个机制。发现分支与总述矛盾，先修订整体模型，再回改所有定义、图与实例，不追加一条例外了事。

先对照用户要求说明能力是否已实现、还有什么缺口，再区分当前启用范围、验证范围和后续扩展。“某个新版本或插件尚未提供”不等于通用机制未实现，测试专用实现也不代表真实新版本已可用。检查实现能力，要沿实际调用追到消费位置；“接口存在、数据被写入、恢复真的使用它”是不同证据。职责目标、待选方案、设计理由和推断另行标明；反常识行为需要可查证依据、理由或明确的未知，不能把实现存在本身当成价值论证。

涉及外部动作时，区分未开始、已发生、确认已收到和结果未知；重试说明查询、复用、覆盖或拒绝的条件。持久状态与内存缓存、记录引用与真实文件、材料查询与实际执行分别说清。

## 修订与交付：审查理解，不只审排版

收到“太多、太空、看不懂、前后不连贯”等反馈，回查范围、背景、抽象层次、因果、实现关联和信息分层；保留仍有效的主干、图与查阅入口，不只缩字数或增加卡片。同类纠正再次出现时暂停扩写，检查整条说明还有哪些同类遗漏。

先从标题与原始请求独立提出应能理解的内容，再沿一条使用过程和必要常见变化检查：每次交接是否闭合，关键依据是否在正文或图中直接可见，读者是否仍需跨段自行拼接核心逻辑。具体源码与证据绑定版本及条件；可取得独立复核时，让复核者先读原始任务与成果，不先喂作者清单。

实际打开成果检查连线、字距、图文对应、交互和取回路径。静态源码核对、浏览器展示、运行行为与用户认可分别报告；检查通过不证明读者理解。必要时用代表片段校准，但已有充分方向不重开确认或把阅读考核交给用户。

成套文档按读者任务保留少量稳定入口，新证据融回原位置。另存修订保留稳定主名与递增版本；局部改动沿用原格式与范围，写前核对用户最新手改。链接、锚点、生成入口和独有内容一起维护，不能只换目录或机械拼成长文。

## 研究与方案：证据支持有条件的判断

读者要作什么判断决定检索范围，优先原始资料、实际接口与成熟能力。先核当前已有做法，再比较现状、最小改善和有竞争力的替代；解释复用点、适配、收益、代价及改选条件，不为展示过程编弱选项。许可、依赖与运行条件在真实引入时核对。

观察、解释、建议与未知分开。数量说明口径与分母，数值附版本、条件、真实数据与测法；估计或模拟标明，未知不能当作不存在。主张“更好”须有对应结果证据，无可比证据就报告能力与限制，不编排名。强反例若会改变结论，优先查；无关枝节不无限扩搜。

科学图表使用真实数据、单位与标准绘图工具；不要为画图编数。学术引文核原文与发表状态，按任务格式引用，预印本、同行评审和社区经验分开。通用自然表达可参考[推荐扩展](recommended-skills.md)，不把润色变成删除必要背景、逻辑或事实。

## 规格、合同与正式成稿

沿确认模板和授权范围保留指标精度，未知资料列为待确认，不凭内部实现随意增加端口、参数或义务。正文呈现对象、要求、机制、接口、边界与必要限制；过程讨论和后续计划留任务记录，除非用户要求包含。方案、已实现、已验证、运行实例生效与业务验收分别标明；重命名或演示不能替代实施与验收。
