# 人工操作任务单

用于请人独立执行验收或编排交互操作。一般测试原则见[测试](testing.md)；已有模板、数量和目录按项目或用户约定，不强制每项套同一大表。

先确认用户终点与主要失败风险，再划分可独立执行的连续旅程；不能把所有功能串成一条无法定位的长链，也不能只证明上传、打开等中间一步。预期写正确行为，当前缺陷单列，不能固化成“预期失败”。

任务单让执行者脱离聊天也能判断：目的、前置、输入／操作、可见预期、失败去向、费用／时间上限及清理。复杂任务再列必要截图位置、账号和权限边界；不让人猜模型内部状态或必须出现的措辞。非固定输出用可观察的结构和内容判据。

方向确实未定时先用代表旅程或页面校准；已有目标和认可小样直接沿用。共享层只承接环境准备、连接和清理，具体场景与关键断言仍可定位。

执行与整项判定沿[原承诺约束](testing.md#执行与判定忠于原承诺)：逐一覆盖任务单的必要操作与结果，失败不换目标、后台补状态或降低预期。

在实际入口执行到可读取／可交付结果，必要时刷新或重新打开取回。受阻、可重复失败、已知缺陷和通过分别记录，保留页面原文、时间及现场。真实模型、外部服务和副作用按授权显式门控；时间不足时说明已测路径与剩余风险。

自动化代点是自动化证据，不冒称人工体验验收。用户不具备的权限不能靠改角色或直接写库绕过；是否能用公开注册等替代取决于任务已授权范围。
