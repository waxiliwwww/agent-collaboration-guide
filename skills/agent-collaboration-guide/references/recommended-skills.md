# 用现成技能完成任务

先看当前环境提供了哪些技能，选择适合任务和输出格式的一个，读它的 SKILL.md。然后实际使用里面的模板、脚本或方法，协作规约只补用户要求、重要决定、模块配合和最后的检查。已有工具够用的小事直接做，不为用技能再加一套流程。

| 要做什么 | 具体技能 | 怎样使用 |
| --- | --- | --- |
| HTML 网页 PPT、演讲演示 | [guizang-ppt-skill](https://github.com/op7418/guizang-ppt-skill) | 以它的模板、布局、制作和演示检查为主，带入已确认的受众、内容和样稿。需要原生可编辑 PPTX 时选择 `ppt-master` 等对应技能。 |
| 去套话、改写说明、自然写作 | [human-writing-skills](https://github.com/whh110112/human-writing-skills) | 读入口后选当前文种所需的模块；技术说明可使用 generation-quality 和 formal-document，重写已有文本时检查 rewrite-fidelity。保留事实、必要背景、引用与作者意思，不用小说规则给技术文档添加装饰。 |
| 写测试、清理无效测试、检查交付证据、处理反复错误 | [prove-it](https://github.com/nagi-studio/skills/tree/main/skills/rookie/prove-it) | 使用行为测试、检查是否真能发现错误及防止重犯的方法。它不代替架构、安全和业务方面的独立判断。 |

这里列的是可核对的具体候选，不表示当前机器都已安装。`de-ai-writing` 是[话题页](https://github.com/topics/de-ai-writing)，用于找候选，不能直接当作一个技能调用。

## 没装或不适合时怎么办

需要某个技能时，先检查已有安装；没有则核对具体项目的说明，给出为什么适合、安装哪个技能和装到哪里。已有明确安装授权直接沿用，否则先取得决定。技能集合先选单项，不整个仓库一键装上。

仅在当前任务读取公开的写作说明并采用方法，和完成安装、运行 CLI 是不同事情，反馈时说清做到哪一步。既不能因为没安装就假装调用成功，也不能只贴推荐链接就声称已经复用。无法使用时说明原因，继续能独立完成的部分。

## 和当前任务合在一起用

把已有计划、样稿、测试和项目脚本交给选定技能，复用已完成步骤和有效证据，不因为换技能重新访谈、批准或跑全量测试。

用户要求、项目规则和已有授权仍然有效。第三方技能默认要求的联网安装、付费调用、改 AGENTS、删测试或破坏实验，不自动获得许可。根据实际被测能力和风险选检查；正常模块隔离不一概算无效替身，低影响文档修改也不因此强制新增浏览器测试、逐步截图或规则表。

有冲突就说明具体影响，采用能满足当前要求的方法；只有重要取舍才让用户决定。未使用的能力不用额外叠加。

来源及模块于 2026-11-11 核对，公开包只保留链接和独立说明，不分发第三方实现。版本、安装状态和工具能否运行，使用时实际核对。本规约没有外部技能时也能使用。
