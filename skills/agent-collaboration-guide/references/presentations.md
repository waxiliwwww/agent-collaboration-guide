# PPT 与演讲汇报

PPT 围绕听众要理解和判断的事组织。通用讨论、授权与检查沿[总入口](../SKILL.md)；本篇补充演讲主线、小样和实际演示要求。

## 先沟通讲法，再制作代表页

读材料并沿用已确认的受众、场合、时长和用途，弄清听众已有背景、听后应记住什么、需要作何判断或配合。给出有依据的推荐主线与简明逐页计划：每页回答什么问题、希望得到什么判断、用什么事实或材料、适合怎样展示。页数服务表达，不按源文件目录搬运，也不先套模板填内容。提供材料、选工具或内部写好大纲不能代替主线交流。

项目进展汇报可按“整体目标与交付→负责部分及衔接→节点与依赖→实际进展和成果→困难与所需支持→下一步及希望确认的事项”展开，按用途调整。先让听众看清项目全貌，工具和测试细账用于支持相应判断；影响结论的限制留在相关页，补充细节按需放备注或附录。

主线对齐后，先展示少量有实际内容的代表页，通常两三页，覆盖主要讲法、信息密度、图表与视觉风格；缺材料明确标注。用户认可并落实反馈后再批量制作，不能把沉默当认可，也不先做整套再补称小样。前提未变的主线与小样直接复用；局部文字、数据和排版修改只核对受影响内容，受众、核心观点或视觉方向实质改变时再校准相应部分。

## 制作与验收

使用用户已选工具；使用 PPT Master 时读取有效技能，把已对齐的主线、逐页计划与认可小样作为依据，技能内部规划不代替沟通。整套沿用已认可的表达，按页面作用安排图文，不机械复制版式。实际进展、预期目标和待验证事项分别说明，不编造成绩或节点。需要在 PowerPoint／WPS 修改提交时，交付可编辑 PPTX，并核查文本、图形和表格的实际编辑能力。

交付前沿演讲顺序串看：标题与关键图表能否串起主线、支撑结论，关键成果是否有实际展示，页面是否承接，正文是否适合时长与观看距离，最后是否落到明确判断或行动。讲稿按需提供，关键关系仍须在页面讲通；如实说明桌面打开、放映与编辑验证的完成范围。
