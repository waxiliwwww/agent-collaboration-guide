# 代码与分支

用于代码、脚本及 Git 协作；需求、授权与通用三步沿[总入口](../SKILL.md)，本篇只补实现、验证和版本操作约束。项目路径、分支、运行入口和命令以目标项目当前约定为准。

## 实现与运行验证

接手先了解项目入口、依赖、现有测试和运行方式。沿用代码风格与测试组织；未有约定时采用目标语言常用规范。测试与业务代码分开，优先复用已有目录与命令；独立功能给能验证实际行为的用例，文字等低影响修改使用相应检查，不写只重复实现的测试。可独立使用的脚本按项目惯例交代用途与运行方式，可调参数集中通过命令行、配置或环境变量传入；不写死个人路径、凭据。配置默认值、加载顺序和兼容性应能查清。命名可懂，注释解释原因与边界；被反复误读的反常行为在实现附近说明。

异常须能定位原因并形成明确结果，不能吞错或伪报成功。关键操作用结构化日志记录时间、级别与关联上下文，必要进度可见，详细信息按需入文件，凭据与用户数据按最小必要原则保护。长时作业、断点续传和提交操作说明中断后的恢复方式，验证重复执行不会造成重复副作用或漏处理。依赖按既有清单维护，更新时核对兼容性与已知安全问题；直接引入第三方代码或资产时核对许可和维护条件。

验证绑定实际工作树、完整提交号、未提交差异，以及依赖、构建、配置和数据条件；保存用例目的、输入或操作、预期与实测、命令和原始输出。优先复用已有检查，先查局部正常、关键失败和必要边界，交接或集成时再查受影响组合；全量回归沿项目 PR 或发布约定集中安排。复用仍有效的同版本、同环境证据，只为改动、失败或未决风险补测，充分后停止。

测试观察用户可感知的结果或明确契约，不照抄当前输出作答案，也不绑定无关内部写法。替身可隔离依赖，不能替掉正被验证的关键能力后宣称它已通过。新增或调整关键检查时，按风险用原问题或代表反例确认确能报错，再恢复验证；不适合构造反例时说明原因与替代证据。只有实施者能察觉的退化，补必要回归或说明无需增加的理由。涉及界面交互时沿实际入口操作，按需保留截图或渲染证据。

功能验证沿用户受影响的完整通路进行：实际入口、跨模块交接、状态与数据流转、实际生效配置，直到结果可取回并继续使用。首次可运行时尽早演练，交付组合再复核受影响部分。按风险检查正常完成、有关失败与取消、自动恢复及必要人工介入：错误在哪里发现，谁处理，何时停止，资源和已有成果怎样处置，之后如何继续。自动恢复须有限制且不重复产生副作用；人工介入须有可见原因、操作入口和可行的后续步骤。保留首次失败、真实处置和终态，临时改配置或代码后重跑成功不能算系统自动恢复。模拟、模块通过或静态推断只支持各自范围；环境准备失败、未演练的路径和业务结果尚未验收分别说明。

新增热路径 I/O、等待或必跑检查时，先定合理性能预算与测法，再记录改前改后耗时、运行条件、次数和取值方法。运行生效另核对进程入口与工作目录、构建产物、有效配置、依赖、数据位置及必要的健康和实际操作；工作树隔离不等于服务与存储隔离。提交、构建或源码集成不能单独证明运行实例已更新。

## 工作树归属与会话待办

多会话并行或无法确认当前目录独占时，编码使用独立主题工作树；已有归属明确的工作树继续使用。明确独占的小修与只读任务可复用当前目录。开始或恢复时绑定仓库、目录、分支、起点提交和已有修改；写入、提交前重验归属。路径或分支不符先纠正，不改写、切换、清理其他会话资源，也不带走其未提交内容。新工作树位置沿项目约定，未规定时放在仓库外相邻目录。

待办优先沿用本会话已有清单。项目没有本地记录约定时，可在当前工作树用 `git rev-parse --path-format=absolute --git-path agent-todo.md` 定位独立 Git 元数据中的清单；不能假定 `.git` 是目录。给出实际路径，项目已有任务入口保留定位方式，不为会话记录新增共享配置或修改他人忽略规则。切换工作树仍指向同一总清单；移除工作树前，将未完成事项、有效要求及必要证据保存或移交到持久位置并核实可读。独立元数据可能随工作树删除，不能作为永久档案。

## 合并保全与串行集成

合并、变基、同步、移植、提交或更新 PR 前，固定双方完整提交、共同基线、未提交内容及正在进行的 Git 操作，保存原 tip 与必要恢复内容，不只依赖短期 reflog。相关远端引用需实际获取才称为已核实。分别检查“共同基线→目标”“共同基线→待合入”的需求、提交说明、实现、配置和测试；两端直接差异、提交新旧或数量不能证明该保留谁。没有唯一共同基线或历史已改写时，先查清关系，不随手选基线。

**逐步解析冲突，结合关联改动保全双方仍有效的意图**，包括功能、修复、性能、配置、兼容性及有意删除。无冲突也须核查行为抵消；不因旧代码仍在就恢复已取消功能。无损机械处理自主完成，等效整合需有依据；拿不准双方意图、会舍弃有效行为或改变主要代价时，说明双方目的、影响、选项与推荐，请用户确认后再处理。不要仅问选 `ours` 还是 `theirs`；其含义随 merge／rebase 不同。不得用批量选边、跳过提交或删除失败测试掩盖问题；锁文件和生成物先对齐源信息，再沿原命令生成，复用旧冲突解法也要复核。

候选完成后从双方视角检查哪些成果保留、等效替代、按决定取消或尚未核实，特别核对冲突块外的调用、默认值、加载顺序、迁移和异常路径。变基可用 `git range-diff` 辅助检查补丁变化，仍须验证最终行为；历史包含或补丁相似不等于功能等效。验证双方有关的关键行为与相互作用，配置看实际生效值，性能主张用适用测量。原有失败、新回归、环境受限与未运行分别保留；目标或候选变化后刷新检查，远端合入不同组合也不能套用旧结论。

用户已采用本机统一工作线时，任务默认完成独立提交与验证、串行合入统一分支、更新固定测试树及清理本任务资源；仅交候选、推主题分支或开 PR 不算本机收尾完成。已有负责人就主动交接并核实；没有且无其他集成进行时，本会话承担收尾，不逐阶段重问既定意图。具体目标从项目入口读取，未确定时先确认，不自行另造常驻汇总线。沿项目既有串行机制，在检查至更新期间保持本轮集成权；无法确认排他时先等待或协调，失败短路命令本身不提供并发互斥。

1. 以固定测试树当时最新的统一分支完整提交作为 `candidate_base`，在归属明确的候选树整合本任务与必要更新，完成上述功能保全及适用验证。旧开发基线或未刷新的远端引用不能代替此起点；候选已完整、未变且证据仍适用时可复用。
2. 更新前，在**同一条失败即停止的执行链**核对：固定树仍在 `candidate_base` 且干净；候选仍在已验证完整提交且干净；该提交包含起点。全部成立才以 `git merge --ff-only <已验证提交>` 推进固定树，随后确认 HEAD、源码及干净状态。该命令不代替候选整合与验证。
3. 目标已推进则基于新起点刷新候选、复核新增差异与受影响组合后继续；验证失败、目录变脏、归属不清或取舍未决时停止更新并说明阻碍，不强制覆盖。长期汇总线通常用普通 merge 保留原提交，上游更新也先验证候选，无需删树重建。
4. 确认提交已合入、证据和接续事项已持久保存、本任务树无人使用后，默认清理已合入的任务树与本地主题分支；有保留用途则说明。远端推送、PR、远端删除与运行更新分别沿既有授权，其他会话资源不代清。

## 提交、交付与回退

每个版本用 commit 留存。提交前核对暂存差异，清楚说明改动、理由、实际验证及必要的兼容和运行限制，使接手者不依赖聊天也能理解。merge 写明合入范围和组合验证，快进不假称产生 merge commit；日常记录留在提交，项目发布流程或用户另有要求时才维护额外 CHANGELOG。发布沿项目版本约定，必要时用语义版本与 tag 固定，创建和推送标记沿既有授权。共享历史补说明优先追加，并区分原验证与本次新验证；变基或强推需已有授权，核对远端 tip，用带明确预期提交的 lease，拒绝后重新查证，不能改裸强推绕过。

交付写明仓库、完整分支名与提交号，分别报告本地提交、本机集成、远端推送／PR、资源清理和当前运行状态及其验证范围。是否推送须核对实际远端与刷新后的对应分支；相对目标分支独有不等于未推送。

回退或清理先辨认改动归属、暂存与未暂存、未跟踪内容、服务及数据影响，保存恢复点。受 Git 跟踪不代表修改属于自己，未跟踪也可能是用户材料。共享改动优先用 revert 保留历史；查看旧版优先临时树，取消暂存不等于丢弃。移除工作树不自动删除分支，分支删除保护也不单独证明成果已合入；压缩合并导致拒绝时核查实际内容，不直接强删。命令超时或失败先确认进程和已产生修改，再决定恢复；不用无条件 `reset --hard`、`clean` 或整目录删除清场。
