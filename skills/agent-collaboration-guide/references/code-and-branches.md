# 代码与分支

用于代码、脚本及 Git 协作；任务目标和授权按[技能主文](../SKILL.md)处理，下面说明实现、验证与 Git 操作。项目路径、分支、运行入口和命令以目标项目当前约定为准。

## 实现与运行验证

从能满足已确认需求的简单实现开始，先核对现有机制为何不足，优先复用或小幅调整。恢复时先区分“继续用户任务”和“重启旧执行单元”，检查原有用户入口能否承接，不因内部尝试耗尽就直接新增恢复控件或重置旧对象。新增状态、字段、计数、抽象或兼容分支须对应具体缺口，能说明由谁使用、现有机制为何不能承担；不为尚未出现的需求预建框架。必要的权限、兼容和恢复保护仍须完整。

修改异步过程的界面反馈时，先沿真实事件梳理等待、内容到达、动作执行与结束的展示归属和交接；同一阶段由一处承担主要提示，已有内容足以说明进展时不叠加同义状态。用真实信号区分准备与执行、过程说明与最终结果，尚未确定的内容不能提前呈现为已结束。替换占位、折叠或切换阶段时，核对原承诺的计时、详情入口、位置及阅读状态是否保留；具体默认样式和格式留在项目决定，不推广成所有产品的规则。

参考成熟产品时，核对可取得的实现及适用模式，复用状态归属和交接机制，再适配当前项目的事件语义与已有组件；截图或单一默认模式不足以证明整体适合。复用后的检查仍沿本项目的真实调用与使用过程，不能只凭外观接近交付。

功能修通后，收拢本次引入的重复判断、多份事实和无效分支，检查新增测试是否守住独有行为或风险。局部整理以本次及必要关联为界；模块拆分和历史架构债务可另行安排，只有妨碍本次正确实现或验证的部分才纳入必要修复，也不能以以后重构为由放任本次新增的冗余。

审查增量时分别说明既有问题、本次引入或加重的问题，以及各自对当前交付的影响，不用遗留大文件替代对增量必要性和正确性的判断。代码规模先区分生产逻辑、测试支撑、文档、生成物与移动或格式变化；行数、文件大小、测试数量和 CI 通过均不能单独证明过度设计或实现合理。仅看最终差异无法确认开发时是否先尝试简单方案时，明确证据边界。

接手先了解项目入口、依赖、现有测试和运行方式。设计测试、检查证据或复核反复问题时，可使用 [prove-it](https://github.com/nagi-studio/skills/tree/main/skills/rookie/prove-it) 的相关方法；先读技能说明再使用。沿用代码风格与测试组织；未有约定时采用目标语言常用规范。测试与业务代码分开，优先复用已有目录与命令；独立功能给能验证实际行为的用例，文字等低影响修改使用相应检查，不写只重复实现的测试。可独立使用的脚本按项目惯例交代用途与运行方式，可调参数集中通过命令行、配置或环境变量传入；不写死个人路径、凭据。配置默认值、加载顺序和兼容性应能查清。命名可懂，注释解释原因与边界；被反复误读的反常行为在实现附近说明。

读取、诊断与写入按实际动作、数据和风险分别设计边界，不因目录命名或复用写入校验阻断已授权的正常读取。执行配对所需的关系或编号，只有在只读摘要、导出等消费者确实需要时才作为其输入条件，不能照搬后丢弃合法历史；恢复信息缺失还须追查保存与恢复源头。权限与审批须有具体需求依据，保留已确认保护及敏感信息、破坏性操作和多用户隔离边界。

异常须能定位原因并形成明确结果，不能吞错或伪报成功。区分调用失败、输出未完成和完整结果验收失败，再选择重试或调整策略；不能把尚未获得完整结果当作语义要求不满足，直接修改提示词或输入规则。关键操作用结构化日志记录时间、级别与关联上下文，必要进度可见，详细信息按需入文件，凭据与用户数据按最小必要原则保护。长时作业、断点续传和提交操作说明中断后的恢复方式，验证重复执行不会造成重复副作用或漏处理。依赖按既有清单维护，更新时核对兼容性与已知安全问题；直接引入第三方代码或资产时核对许可和维护条件。

已确认的兼容与演进承诺写入项目开发约定，并由必要回归保护；明确旧数据读取、查询和更新以及新数据写入的边界，区分保存表示与业务接口。测试库可重建，不等于允许破坏已承诺保留的数据；已有实现先核对缺口，不为响应"实现它"而重复改造。

验证时记录实际工作树、完整提交、未提交差异，以及依赖、构建、配置和数据条件，保存实际命令与原始结果。用例设计、按风险选测、证据复用与失败处理使用[测试原则](testing.md)，不另建检查清单；界面交互按需保留实际操作与截图证据。

验证改动时，按用户完整使用过程检查：实际入口、跨模块交接、状态与数据流转、实际生效配置，直到结果可取回并继续使用。首次可运行时尽早演练，交付组合再复核受影响部分。按风险检查正常完成、有关失败与取消、自动恢复及必要人工介入：错误在哪里发现，谁处理，何时停止，资源和已有成果怎样处置，之后如何继续。自动恢复须有限制且不重复产生副作用；明确尝试的计数对象、作用区间和耗尽后状态，不能无依据地把旧自动循环的耗尽状态延续到用户新请求，后台自动重排队也不能自续预算。累计用量、真实配额与权限仍按原规则，原操作身份与回执保留。人工介入须有可见原因、既有入口能承接的操作和可行后续；确需新入口时说明原机制的具体缺口。保留首次失败、真实处置和终态，临时改配置或代码后重跑成功不能算系统自动恢复。模拟、模块通过或静态推断只支持各自范围；环境准备失败、未演练的路径和业务结果尚未验收分别说明。

新增热路径 I/O、等待或必跑检查时，先定合理性能预算与测法，再记录改前改后耗时、运行条件、次数和取值方法。预算应覆盖整条调用路径，包括前置扫描、隐式加载、并发与重试；限制返回条数或停止等待，不能单独证明计算、内存或实际执行已经受限。运行生效另核对进程入口与工作目录、构建产物、有效配置、依赖、数据位置及必要的健康和实际操作；工作树隔离不等于服务与存储隔离。提交、构建或源码集成不能单独证明运行实例已更新。

## 推荐的默认开发流程

对尚未建立约定的仓库，推荐采用以下流程：**独立 worktree 开发 → 已验证提交串行合入本机主分支 → 由本机主分支提交 PR 到远端开发分支**。

先核对仓库规则、分支与已有授权；能确定流程和目标时直接沿用，不因首次接触仓库例行询问是否采用推荐流程。只有影响交付的重要未知或未授权变化才说明选项并确认，不能用推荐覆盖项目约定。

开 PR 前固定范围，以本机主分支汇总属于本次的已验证提交，抓取远端开发分支并解决冲突，验证后把整合结果快进回本机主分支。PR 合入后抓取远端，核对本机主分支是否已包含合并结果；需要时整合并验证，保留本机独有提交。


## 工作树归属与会话待办

多会话并行或无法确认当前目录独占时，编码使用独立主题工作树；已有归属明确的工作树继续使用。明确独占的小修与只读任务可复用当前目录。开始或恢复时绑定仓库、目录、分支、起点提交和已有修改；写入、提交前重验归属。路径或分支不符先纠正，不改写、切换、清理其他会话资源，也不带走其未提交内容。新工作树位置沿项目约定，未规定时放在仓库外相邻目录。

待办优先沿用本会话已有清单，先核对所属任务、当前仓库、工作树和分支；默认路径中存在旧清单不代表本轮已有记录，旧任务的完成标记不能沿用。项目没有本地记录约定时，可在当前工作树用 `git rev-parse --path-format=absolute --git-path agent-todo.md` 定位独立 Git 元数据中的清单；不能假定 `.git` 是目录。给出实际路径，项目已有任务入口保留定位方式，不为会话记录新增共享配置或修改他人忽略规则。切换工作树仍指向同一总清单；移除工作树前，将未完成事项、有效要求及必要证据保存或移交到持久位置并核实可读。独立元数据可能随工作树删除，不能作为永久档案。

本次任务的提交／PR 范围先固定，其他会话的新改动默认保留，不自动追赶、并入或等待其收尾。确需依赖时解释最小纳入范围与影响，沿已有授权处理；目标分支的必要更新和冲突仍应完成，不以范围固定跳过集成核查。

## 合并保全与串行集成

合并、变基、同步、移植、提交或更新 PR 前，先固定双方状态：完整提交、共同基线、未提交内容及正在进行的 Git 操作，保存原 tip 与必要恢复内容，不只依赖短期 reflog。相关远端引用需实际获取才称为已核实。

### 分析双方意图，不靠代码新旧选边

分别检查"共同基线→目标""共同基线→待合入"的需求、提交说明、实现、配置和测试；两端直接差异、提交新旧或数量不能证明该保留谁。没有唯一共同基线或历史已改写时，先查清关系，不随手选基线。

**逐步解析冲突，结合关联改动保全双方仍有效的意图**，包括功能、修复、性能、配置、兼容性及有意删除。无冲突也须核查行为抵消；不因旧代码仍在就恢复已取消功能。无损机械处理自主完成，等效整合需有依据；拿不准双方意图、会舍弃有效行为或改变主要代价，以及按用户配置或项目约定分为中、高等级的新取舍或原决定实质变更，均先说明双方目的、用户可见影响、选项与推荐，取得用户明确确认后再实施受该决定影响的改动。范围、条件未变的已确认决定直接沿用。不要仅问选 `ours` 还是 `theirs`；其含义随 merge／rebase 不同。不得用批量选边、跳过提交或删除失败测试掩盖问题；锁文件和生成物先对齐源信息，再沿原命令生成，复用旧冲突解法也要复核。

### 整合后核对保全结果

整合完成后分别检查两边的成果：哪些保留、哪些被同等实现替代、哪些按决定取消、哪些还没核实，特别核对冲突块外的调用、默认值、加载顺序、迁移和异常路径。涉及双方改动时，提交或更新 PR 前，将上述保全结论及相关用户决定、实际验证覆盖的双方行为与组合、未测或受限缺口，简要并入现有任务反馈或 PR 说明；未决取舍先在对话中提出，不另建台账或审批轮次，也不以无文本冲突或测试全过代替保全审查。变基可用 `git range-diff` 辅助检查补丁变化，仍须验证最终行为；历史包含或补丁相似不等于功能等效。验证双方有关的关键行为与相互作用，配置看实际生效值，性能主张用适用测量。原有失败、新回归、环境受限与未运行分别保留；目标或候选变化后刷新检查，远端合入不同组合也不能套用旧结论。

### 串行集成流程

用户已采用本机统一工作线时，任务默认完成独立提交与验证、串行合入统一分支、更新固定测试树及清理本任务资源；仅交候选、推主题分支或开 PR 不算本机收尾完成。执行集成的 Agent 负责该次集成的收尾；换人时按技能主文核实接手，没有接收方时不默认交给用户或其他会话，不逐阶段重问既定意图。具体目标从项目入口读取，未确定时先确认，不自行另造常驻汇总线。沿项目既有串行机制，在检查至更新期间保持本轮集成权；无法确认排他时先等待或协调，失败短路命令本身不提供并发互斥。

1. 以固定测试树当时最新的统一分支完整提交作为 `candidate_base`，在归属明确的候选树整合本任务与必要更新，完成上述功能保全及适用验证。旧开发基线或未刷新的远端引用不能代替此起点；候选已完整、未变且证据仍适用时可复用。
2. 更新前，在**同一条失败即停止的执行链**核对：固定树仍在 `candidate_base` 且干净；候选仍在已验证完整提交且干净；该提交包含起点。全部成立才以 `git merge --ff-only <已验证提交>` 推进固定树，随后确认 HEAD、源码及干净状态。该命令不代替候选整合与验证。
3. 目标已推进则基于新起点刷新候选、复核新增差异与受影响组合后继续；验证失败、目录变脏、归属不清或取舍未决时停止更新并说明阻碍，不强制覆盖。长期汇总线通常用普通 merge 保留原提交，上游更新也先验证候选，无需删树重建。
4. 收尾时重新查询 `git status --short`、`git worktree list --porcelain` 及本地分支与提交关系，逐一核对本轮创建或接管的资源；主树干净、提交已合入不能代替资源清理。确认集成结果、证据和接续事项已持久保存、本任务树无人使用后，默认移除已完成的任务树及本地主题分支，再查询一次确认实际结果；删树不代表分支也已删除。保留或受阻事项沿主干记录原因和接续责任。远端推送、PR、远端删除与运行更新分别沿既有授权，其他会话资源不代清，其正常保留不算本轮清理遗漏。

## 提交、交付与回退

每个版本用 commit 留存。提交前核对暂存差异，清楚说明改动、理由、实际验证及必要的兼容和运行限制，使接手者不依赖聊天也能理解。merge 写明合入范围和组合验证，快进不假称产生 merge commit；日常记录留在提交，项目发布流程或用户另有要求时才维护额外 CHANGELOG。发布沿项目版本约定，必要时用语义版本与 tag 固定，创建和推送标记沿既有授权。共享历史补说明优先追加，并区分原验证与本次新验证；变基或强推需已有授权，核对远端 tip，用带明确预期提交的 lease，拒绝后重新查证，不能改裸强推绕过。

交付明确标注本地与远端：本地提交在哪个分支、合入哪个本地分支及其 HEAD；远端推送到哪个远端名与分支，PR 的源／目标分支及实际合入状态。即使两边同名也保留"本地／远端"标签，不只写"main:HEAD""已合入＋提交号"让用户猜归属；HEAD 是某个工作树当前提交，`origin/main` 是最近获取的远端跟踪快照，不能单独证明此刻远端状态。可简写"本地 main：已合入，HEAD abc123；远端 origin/main：已推送并核实 abc123"。未推送／未合入／未核实分别直说，再报告资源清理、运行状态及其验证范围；仓库有歧义时补定位，无需机械重复完整路径或哈希。是否推送须核对实际远端与刷新后的对应分支；相对目标分支独有不等于未推送。PR 创建或更新后，继续核对最新提交的检查结果与可合并状态，推进到约定交付终点；范围内的检查失败自主修复。区分已提交、检查通过、可合并和已合并，排队／运行中不算通过，旧提交结果不能证明新提交。外部阻塞时说明当前提交、阻塞与接续安排，不假称完成；核对状态不扩大自动合并、发布或持续监控的授权。

条件触发的后续动作沿已确认授权执行，说明实际执行机制、持续运行前提、失败／超时停止条件及结果入口；本机监控不等于平台托管。"已安排、等待中、已执行、最终生效"分开报告，最终核对远端或实际对象的终态。

清理限本任务已完成的临时资源；项目约定的长期分支不因引用落后或没有工作树而删除。未合入内容先核对仍有效、已等效替代或明确取消的部分，再决定整合或保留恢复依据，不按祖先关系或旧实现的存在整批丢弃／恢复。回退或清理先辨认改动归属、暂存与未暂存、未跟踪内容、服务及数据影响，保存恢复点。受 Git 跟踪不代表修改属于自己，未跟踪也可能是用户材料。共享改动优先用 revert 保留历史；查看旧版优先临时树，取消暂存不等于丢弃。分支删除保护不单独证明成果已合入；非祖先分支先核对补丁等效、后续变更及保留价值；压缩合并导致删除被拒绝时不能就此长期搁置，也不凭补丁等效单独强删。命令超时或失败先确认进程和已产生修改，再决定恢复；不用无条件 `reset --hard`、`clean` 或整目录删除清场。
