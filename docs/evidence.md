# 验证与已知限制

## 目前能够说明什么

0.8.1 针对选测遗漏消费者、未先核对实际 CI 范围和 PR 状态收口不清，细化既有测试与交付扩展。原入口已要求完整交付与证据核验，此次主要补具体落点，不能将执行遗漏全归因于规则缺失。验证限于元数据、相对引用、独立导出、更新器既有边界及安装公开文件一致性与私有数据保留；未开展真实 PR 行为演练，不能据此声称已消除同类遗漏。

0.8.0 将已有“完整交付”原则落实为开工／恢复、修改与验证、交付收口三处可追查依据，复用现有Plan；没有增加统一执行服务。一次未参与起草者的前向演练先处理两个请求，再审阅技能：复杂案例要求成熟的双入口、双输入数据转换产品，评估者保留原完整目标，将两个新报错作为既有功能缺陷，提出合法变化、连续操作和真实导出内容的证据要求，没有虚构实现或通过结论；单字修改案例实际只改一个字节，两处CRLF和末尾无换行保持。审阅未发现阻断项，独立复核句的适用范围据低风险意见就地明确为重要或高风险交付。

本轮另验证技能元数据、相对引用、独立导出及更新器9项保留／拒绝边界。复杂案例只做接手安排，未开发或运行产品；两次代表演练与结构检查不证明长期减少遗漏，更不证明任何产品成熟。后续真实任务是否按原目标收口、是否减少同类遗漏仍须观察，不能用本次通过代替。

0.7.0 将入口、按需扩展、私有偏好和反馈闭环重新接线。更新器的 9 个边界用例验证：公开更新、私有数据保留、导出排除、无效源／只预览、目的地及私有链接、公共目录读取失败。另以临时故障版本删除 local/，保留测试会失败；这证明检查可捕获该种回归，不证明所有更新器都安全。

一次独立前向演练只获得入口、直接需要的参考和[教学源码摘录](fixtures/csv-import-source.md)，用户请求为“写一份 CSV 导入服务运行机制 HTML，读者有编程和数据库基础，不熟悉该服务”。未给预期答案。首稿主动使用交接 SVG，解释提交键、数据集并发、批次事务、恢复位置与内存边界，并标明源资料未提供的清理／跨 Server 等能力。另一个公告改词请求只作所需替换，字节比对确认其他内容和换行未变。演练没有运行真实导入服务，文档的静态结构检查不证明读者已理解。

偏好迁移另由独立审阅对照原始两源，修回具体授权和成本边界。独立代码审阅发现并修正了链接路径与目录读取错误处理问题；这些结论与长期行为改进分开。上述少量样例不是对照试验，不证明以后所有任务都更快收敛；本轮原复杂文档仍有未完成问题，不能计作成功验收。

公开版是在已有协作规约基础上重新组织的早期技能发行，尚没有足以证明该技能优于其他协作方法的同条件效果试验。

## 形成过程中的观察

此前对规约的精简与调研方法做过小规模对照。旧长版与精简版的短调研结果接近，精简版仍有遗漏；这支持继续减少分散和重复，不能据此声称质量稳定提高。

另一次试验只修改两处调研文字，用两个未见主题各作两次版本对照，再加一道窄题，共十份首稿。两位匿名 AI 审阅者中，一位仅在一组对照看到局部改善，另一位认为全部持平；候选没有达到预先确定的合入条件，最终没有发布。没有通过追加提醒来宣称问题已解决。

这些试验评价的是当时的规约版本和短调研交付，并非本次技能包；样本小、执行与审阅来自同一模型系列，未有真实用户体验验收。公开仓库不包含原始私人会话日志，因此读者不能仅凭本页独立复现当时结果。这些观察是形成背景，不是可复现的公开基准或性能证明。

## 怎样在自己的任务里判断是否有用

用真实任务观察有意义的行为：该澄清的方向是否在大规模实施前解决；已回答事项是否被沿用；确认的功能和失败处理是否完整；反馈能否写回并接续；状态、证据和剩余问题能否讲清。

同时记录用户介入、等待首份可用结果和维护材料的成本。问题少、文档多或测试多都不能单独代表进步；原任务本已清楚且小改直接完成，也是正确使用。

同时检查约束两端：是否遗漏常见入口、必要交接或静默改写有效决定；是否重复确认、要求机械填表或让用户补做本可自行完成的工作。无可比基线时报告达成情况和发现的问题，不从一次成功推断改善幅度。

比较方法时使用新任务、相同资源和独立首次结果，先定与原需求有关的判断标准，保留失败与分歧。若没有观察到收益，优先撤回无效规则，而不是不断改题或放宽门槛。

## 能力边界

技能不能替代工具权限、执行审批、CI 或分支保护，不能保证每次被自动选中，也不能保证不同模型和宿主同样遵守。需要运行时硬限制的项目，应沿其已有执行点实现和验证；这不在当前发行范围内。
